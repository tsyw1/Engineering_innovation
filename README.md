# Engineering_innovation

2026 年工创赛智能搬运机器人 STM32 固件工程。

本工程的目标是控制一台基于 `STM32F407VET6` 的全向麦轮搬运车，完成二维码解析、两批物料搬运、粗加工区放置/取回、暂存区放置、同色码垛以及回到指定启停区的完整比赛流程。

> **当前运行入口**
>
> `Core/Src/main.c` 是当前完整比赛流程入口。上电后初始化串口屏、二维码 UART4、视觉 USART3、HWT101 航向传感器、CAN 电机总线、机械臂、料盘和任务状态机；收到串口屏 `0x31` 或 `0x32` 启停区命令后，任务 1 在行驶过程中接收二维码并构建任务计划，随后按任务 1～10 顺序运行。任务 2、3、4、5、6、7、8、9 均接入视觉模式切换和视觉微调，任务 10 完成后底盘停止并失能。
>
> 二维码任务码只在任务 1 成功解析后提交给后续任务；视觉帧由 USART3 中断接收、主循环解析，并由各任务在到位前执行目标选择、微调和新鲜度检查。第 6.1 节保留固定动作表，作为机械臂角度、等待时间和安全顺序的参考。

## 2. 硬件与外设映射

目标 MCU 为 `STM32F407VET6`，系统时钟由 HSI 经 PLL 配置为 168 MHz：

- HSI = 16 MHz。
- PLLM = 8，PLLN = 168，PLLP = 2。
- AHB = 168 MHz。
- APB1 = HCLK / 4。
- APB2 = HCLK / 2。
- SysTick 用于 `HAL_GetTick()` 和 `HAL_Delay()`。

### 2.1 外设用途

| 外设 | 引脚/配置 | 工程用途 |
| --- | --- | --- |
| CAN1 | PA11/PA12，500 kbit/s | 麦轮电机和机械臂 CAN 电机 |
| I2C1 | PB6/PB7，100 kHz | JY901S 加速度计 I2C 接口 |
| UART4 | PA0/PA1，115200-8-N-1 | 二维码/任务码接收 |
| UART5 | PC12/PD2，115200-8-N-1 | 串口屏通信，接收 `0x31`/`0x32` 启停区命令 |
| USART1 | PA9/PA10，115200-8-N-1 | HWT101 偏航角 UART 接口 |
| USART2 | PA2/PA3，115200-8-N-1 | TTL 电机共享总线 |
| USART3 | PD8/PD9，115200-8-N-1 | 视觉模块 JSON/文本帧接收 |
| USART6 | PC6/PC7，115200-8-N-1 | 调试、状态、错误和位置上报 |
| TIM1 CH1/CH2 | PE9/PE11，周期 20000 | 机械臂两个 PWM 舵机 |
| USART2_TX | PA2 | 机械臂 Z 轴串行总线舵机 |
| CAN1 RX0 IRQ | 优先级 0 | 电机反馈接收 |
| UART4/UART5/USART1 IRQ | 优先级 5 | 二维码、屏幕、IMU 接收 |

`Engineering_innovation.ioc`、`Core/Src/*.c` 和 `Core/Inc/*.h` 是外设配置的最终依据。修改 CubeMX 配置后，必须检查用户代码区是否仍保留应用接入代码。

## 3. 上电后的完整执行流程

下面描述的是当前 `main.c` 已实现的完整应用架构和执行流程。

### 3.1 启动文件到 `main()`

1. Cortex-M4 从向量表进入 `Reset_Handler`。
2. 启动文件完成栈初始化、数据段拷贝和 BSS 清零。
3. 进入 `main()`。
4. `HAL_Init()`：复位 HAL 状态、配置 Flash 接口、启动 SysTick。
5. `SystemClock_Config()`：配置 168 MHz 系统时钟。
6. 按顺序调用 CubeMX 初始化函数：`MX_GPIO_Init()`、`MX_TIM1_Init()`、`MX_UART4_Init()`、`MX_USART1_UART_Init()`、`MX_USART3_UART_Init()`、`MX_UART5_Init()`、`MX_USART6_UART_Init()`、`MX_CAN1_Init()`；使用对应模块时还需初始化 `USART2` 和 `I2C1`。
7. 调用 `app_prepare()` 完成设备驱动和任务状态机准备。
8. 准备成功后进入 5 ms 周期的主循环。

### 3.2 `app_prepare()` 初始化顺序

1. **启动串口屏接收**：调用 `screen_init()` 和 `screen_start_receive()`，先挂接 UART5 单字节接收，保证准备期间点击屏幕的首个有效命令不会丢失。
2. **等待驱动器上电稳定**：`HAL_Delay(2000)`，等待电机驱动器和 CAN 收发器完成上电自检。
3. **启动 CAN 电机总线**：`motor_bus_init()`、`motor_bus_start()`，再等待约 `200 ms`。
4. **初始化机械臂**：`arm_controller_init()` 绑定升降轴 CAN 地址 5、水平轴 CAN 地址 6，并完成夹爪闭合、升降轴碰撞回零、水平轴当前位置清零和 Z 轴转物料盘方向。机械臂只在上电初始化时归零，任务 1 不再重复归零。
5. **初始化麦轮底盘**：`mecanum_chassis_init_default()` 注册 FL/FR/RL/RR 四个轮电机，默认 ID 为 1/2/3/4。
6. **初始化航向闭环**：初始化 HWT101 偏航角串口，等待第一帧有效航向并保存为整轮任务的固定参考航向。
7. **使能底盘与料盘**：使能四轮电机，加载料盘舵机默认配置并初始化。
8. **初始化屏幕统计**：清零成功取料数和放置数。
9. **初始化二维码串口**：`QR_Init()` 清空任务、错误和统计，并启动 UART4 单字节接收。
10. **初始化视觉串口**：初始化 USART3，启动单字节接收；视觉帧在主循环中解析。
11. **初始化任务状态机**：依次调用 `task1_start_qr_init()` 到 `task10_return_home_init()`，所有任务共享底盘、机械臂、视觉微调、料盘和屏幕对象。
12. **发布准备完成状态**：USART6 输出 `competition_flow_ready` 和 `waiting_uart5_0x31_zone1_or_0x32_zone2`。

任一步骤失败都会通过 `app_report_error()` 在 USART6 输出错误事件，然后进入 `Error_Handler()`，关闭中断并永久停机。

## 4. 主循环执行时序

完整调度器每次循环执行以下操作：

```text
screen_rx_task()                 // 恢复被 UART 错误打断的接收
vision_uart_task()               // 解析待处理视觉帧
app_report_chassis_position()    // 更新反馈并输出底盘、航向和运行状态

if 尚未启动且收到 UART5 0x31/0x32:
    锁定启停区
    配置任务1起点和任务10终点
    请求任务1开始

if 未启动:
    HAL_Delay(5)
    continue

task1_step()
若任务1完成 -> 提交二维码到任务2
task2_step()
若任务2完成 -> 提交二维码到任务3
...
task9_step()
若任务9完成 -> 提交二维码到任务10
task10_step()

HAL_Delay(5)
```

任务提交只发生一次，使用 `*_submitted` 标志防止重复提交。每个任务的 `*_step()` 都是状态机入口；任务 1～10 中涉及底盘直线或旋转的动作统一调用 `APP/chassis_motion_closed_loop.c`。直线控制周期为 `20 ms`，原地旋转控制周期为 `10 ms`；同步接口返回前已经完成减速和稳定停车。

### 4.1 公共后台服务

在主循环的非阻塞阶段，`app_report_chassis_position()` 持续运行；闭环底盘动作进入同步控制函数后，由 `chassis_motion_closed_loop.c` 自己消费反馈并执行控制周期：

1. `mecanum_chassis_feedback_task()` 消费 CAN 中断接收的电机反馈。
2. `mecanum_chassis_update_encoder_velocity()` 根据四轮实际 RPM 更新 `V_encoder_x/y`。
3. `arm_controller_hold_z_position()` 周期性保持 Z 轴绝对目标。
4. USART6 输出 HWT101 偏航角、底盘编码器速度和任务运行诊断。

闭环动作内部每个控制周期仍会调用 `mecanum_chassis_feedback_task()`、编码器速度更新和 HWT101 数据读取，因此不会退回到固定速度/固定时长的位置模式。视觉 UART 接收仍由中断缓存，视觉微调只在底盘到位后的状态机阶段执行；机械臂动作仍由各任务原有的 `arm_controller_*()` 状态调用完成。

## 5. 启停区选择与二维码任务码

### 5.1 启停区命令

串口屏 UART5 只接收原始单字节，不需要换行和 `FF FF FF` 结束符：

| 字节 | 含义 | 任务 1 横移 | 任务 10 最后返程 |
| --- | --- | --- | --- |
| `0x31` / 字符 `1` | 启停区 1 | 左移 1070 mm | 后退 1020 mm |
| `0x32` / 字符 `2` | 启停区 2 | 右移 1070 mm | 车体前向 950 mm |

本次上电只接受首条有效启动命令，之后重复点击或切换按钮均忽略。屏幕向 MCU 发送的是单字节命令；MCU 更新屏幕控件 `t0`、`t3`、`t5` 时，仍按 Nextion 协议追加 `0xFF 0xFF 0xFF`。

### 5.2 二维码格式

二维码任务码固定为 15 个有效字符：

```text
XXX+XXX+XXX+XXX
```

`QR_ParseTaskCode()` 解析为四组长度为 3 的数组：第一批颜色、第一批环位、第二批颜色、第二批粗加工环位。颜色码范围为 1～6，位置码范围为 1～3。

`task_plan_build()` 将任务码转为可执行计划：顺序号 0/1/2 对应料盘 1/2/3 号位；第一批暂存环位沿用第一批位置码；第二批码垛目标通过“第二批颜色在第一批中的同色项”查找，不能直接把第二批粗加工环位当作码垛目标；`task_plan_stack_is_valid()` 检查三件第二批物料是否都能找到同色第一批目标。

## 6. 任务 1～10 的当前业务流程

所有距离和等待时间以下列当前代码为准。任务 1 负责接收二维码和构建计划；主循环在前一任务进入 `DONE` 后，只提交一次任务码给下一任务。

### 任务 1：启动、行驶中扫码

文件：`APP/task1_start_qr.c`、`APP/task1_start_qr.h`。

```text
WAIT_START
 -> FORWARD_FIRST                    前进 70 mm
 -> LATERAL_AND_PLATFORM_ROTATE      区1左移1070 mm / 区2右移1070 mm
                                      同时低速将Z轴转到原料平台方向
 -> FORWARD_AND_SCAN                 前进260 mm，UART4持续接收二维码
 -> WAIT_QR_MID                      中途停车，等待识别到有效二维码
 -> FORWARD_SCAN_SECOND              再前进660 mm
 -> WAIT_QR                          读取已经收到的有效任务码
 -> PROCESS_QR                       显示任务码并构建任务计划
 -> DONE
```

- 机械臂只在上电初始化时归零，任务 1 不再重复归零。
- 横移开始前异步下发平台方向命令，Z 轴使用 `100 ms` 运行时间；其他 Z 轴动作仍使用默认 `60 ms`。
- 前进扫码段拆为 `260 mm + 660 mm` 两段；第一段结束后停车等待有效二维码，识别到后再完成第二段，最后进入 `WAIT_QR` 读取任务码。

### 任务 2：第一批原料区平台取料

文件：`APP/task2_platform_pick.c`、`APP/task2_platform_pick.h`。

1. 任务 2 不再执行原来的前进 `830 mm`。
2. 收到任务码后右移 `920 mm`，再前进 `70 mm` 到新的平台取料位置，同时执行首件平台取料预定位。
3. 到位后等待预定位完成，预选物料视觉模式，并按第一批颜色顺序处理 3 件物料。
4. 每件执行“物料盘定位 → 视觉对准 → 平台夹取 → 放入物料盘”，成功后更新屏幕取料计数。
5. 三件物料完成后，先反向补偿视觉微调期间实际下发的底盘位移，再后退 `70 mm` 回到右移 `920 mm` 后的位置。

### 任务 3：第一批粗加工区放置

文件：`APP/task3_coarse_ring.c`、`APP/task3_coarse_ring.h`。

1. 左移 `70 mm`。
2. 原地旋转 `180°`。
3. 右移 `1670 mm` 到粗加工区，同时执行机械臂观察预定位。
4. 底盘停在中心环附近，按第一批位置码选择目标环，由机械臂 Z 轴和水平轴覆盖 1/2/3 号环并逐件放置。

### 任务 4：第一批粗加工区取回

文件：`APP/task4_ring_return.c`。

底盘保持在当前粗加工区位置，按第一批目标顺序逐件夹取地面物料并放回物料盘。放料回收阶段会并行启动下一物料盘工位和下一目标环转向，减少件间重复等待。

### 任务 5：第一批物料放入暂存区

文件：`APP/task5_temporary_ring.c`、`APP/task5_temporary_ring.h`。

1. 根据任务 4 最后一件所在环位后退：1/2/3 号环分别为 `970/830/670 mm`。
2. 顺时针旋转 `90°`。
3. 再后退 `820 mm` 进入暂存区，同时执行机械臂观察预定位。
4. 底盘停在中心区域，由机械臂覆盖目标环并完成第一批 3 件物料放置。

## 7. 中断与数据流

### 7.1 CAN 接收

`CAN1_RX0_IRQHandler()` 只调用 `HAL_CAN_IRQHandler(&hcan1)`。HAL 回调进一步进入 `motor_can.c`，解析电机反馈并更新缓存。主循环调用 `mecanum_chassis_feedback_task()` 消费一致快照，因此中断不执行路径规划或机械臂动作。

### 7.2 UART 接收分发

工程使用统一的 HAL 回调：

```text
HAL_UART_RxCpltCallback(huart)
    -> hwt101ct_on_rx_complete(huart)
    -> motor_ttl_on_rx_complete(huart)
    -> material_tray_uart_control_on_rx_complete(huart)
    -> screen_on_rx_complete(huart)
    -> UART4: QR_ProcessByte()
    -> USART3: vision_uart_process_byte()
```

`HAL_UART_ErrorCallback()` 执行对应模块的错误恢复并重新挂接单字节接收。中断回调只搬运数据、清状态和重启接收，不发送运动指令。

### 7.3 SysTick 与异常

- `SysTick_Handler()` 调用 `HAL_IncTick()`，支撑 `HAL_Delay()` 和超时计算。
- NMI、HardFault、MemManage、BusFault、UsageFault 和 `Error_Handler()` 均进入死循环。
- 应用错误通过 USART6 先输出 `COMPETITION,ERROR,...`，随后停机，便于调试器保留现场。

## 8. 视觉闭环流程

视觉模块通过 USART3 发送帧，`vision_uart.c` 完成行缓存、帧解析、序号连续性和新鲜度检查。

当前 `BSP/vision_fine_adjust.h` 中的 `VISION_FINE_ADJUST_BYPASS = 0`，正式视觉闭环已启用。任务会发送视觉模式命令、等待有效帧并根据像素误差修正底盘；调试时若临时改为 `1`，视觉对准状态会直接判定到位。

1. 任务调用 `vision_fine_adjust_start()` 或预选模式接口。
2. 视觉驱动发送物料模式或靶环模式命令。
3. USART3 中断逐字节接收，主循环 `vision_uart_task()` 解析完整帧。
4. `vision_fine_adjust_step()` 取最新有效帧。
5. 根据像素误差换算为车体 `vx/vy` 或少量位置脉冲。
6. 当 X/Y 误差同时进入默认容差，返回 `VISION_FINE_ADJUST_REACHED`。
7. 无帧、模式不符、目标无效、帧过期或超时会返回对应错误，任务进入失败态。

## 9. 底盘、机械臂和算法协作

### 9.1 麦轮底盘

`BSP/chassis_mecanum.c` 提供速度模式、位置增量模式、反馈和编码器运动学速度。默认电机 ID 为 FL=1、FR=2、RL=3、RR=4，方向符号为 `{1, -1, 1, -1}`，位置模式每转 3200 脉冲。更换电机安装方向后优先修改 `mecanum_config_t` 默认配置，不要在各任务中分别补符号。

任务 1～10 的固定路线直线和旋转动作统一通过 `APP/chassis_motion_closed_loop.c` 执行，不再由各任务直接下发位置增量。该模块复用旧测试程序的闭环参数和逻辑：

- 最大速度 `1.60 m/s`，加速度 `1.70 m/s²`，减速度 `1.55 m/s²`，直线控制周期 `20 ms`；参数集中在 `BSP/chassis_odometry_motion_config.h`。
- 直线运动使用 CAN 编码器速度进行里程计积分，使用 HWT101 航向保持，并对横向误差执行 PI 修正。
- 左移目标额外使用 `CHASSIS_ODOMETRY_LEFT_COMP_M = 0.03 m` 补偿；正车体 `x` 为前进，负 `x` 为后退，正车体 `y` 为左移，负 `y` 为右移。
- 旋转使用 HWT101 当前角度作为目标反馈，正角度为逆时针，负角度为顺时针；旋转速度倍率为 `3.00`，控制周期 `10 ms`。
- 直线停车稳定等待为 `20 ms`，原地旋转停车稳定等待为 `10 ms`。
- 任一动作遇到航向/编码器数据过期、底盘下发失败或超时，任务返回原有的 `*_CHASSIS_ERROR`，由状态机执行视觉中止、底盘停止和失能。

闭环接口是同步调用：`chassis_motion_move_linear_mm()` 和 `chassis_motion_rotate_deg()` 返回时对应动作已经完成。因此任务状态机、二维码提交、视觉模式切换、视觉微调和机械臂动作顺序保持不变。任务 4、任务 8 的底盘保持在粗加工区 2 号环前，本身没有独立直线/旋转动作；其视觉和机械臂状态机仍按原流程运行。

### 9.2 速度解算

当前完整比赛入口使用四轮实际 RPM 经过轮速换算和麦轮逆运动学得到底盘 `vx/vy/wz`，位置闭环由编码器速度积分，偏航角直接采用 HWT101 输出。`Algorithm/JY901S_ACCEL_VELOCITY.*` 仍保留在工程中，但不参与当前 `main.c` 的比赛路线闭环。

### 9.3 机械臂

`BSP/arm_controller.c` 将升降轴、水平轴、Z 轴舵机和夹爪组合成平台取料、粗加工放置、环取回、暂存放置、码垛和回盘动作。动作等待时间、目标角度和脉冲参数集中在 `BSP/arm_controller.h`、各轴头文件及对应源文件中。

## 12. 故障处理与排查顺序

### 12.1 上电后无日志

检查 USART6 波特率、`MX_USART6_UART_Init()`、当前 `main.c` 是否为空主循环，以及准备阶段是否进入 `Error_Handler()`。

### 12.2 屏幕点击无反应

检查 UART5 PC12/PD2 交叉连接和共地；确认发送原始 `0x31` 或 `0x32`，不是带换行的字符串；确认 `screen_start_receive()` 和 `screen_on_rx_complete()` 已接入。

### 12.3 二维码解析失败

检查二维码是否严格为 `XXX+XXX+XXX+XXX`，颜色码是否在 1～6、位置码是否在 1～3，并查看 `QR_GetDiagnostics()`。

### 12.4 视觉微调超时

检查 USART3、视觉模式、帧序号、有效目标和帧年龄；再检查图像坐标到车体坐标的方向符号和像素比例。

### 12.5 底盘方向或距离错误

检查四个轮电机 ID、方向符号、轮径、轮距、轴距和编码器每转脉冲数。先运行直线、横移和原地旋转测试，再运行完整任务。

### 12.6 CAN 总线停止

检查终端电阻、收发器供电、CANH/CANL 极性、500 kbit/s 配置、`CAN1_RX0_IRQHandler()` 和 `HAL_CAN_RxFifo0MsgPendingCallback()`。进入 `Error_Handler()` 后需要复位 MCU。

## 13. 修改代码时的边界

- CubeMX 生成文件中的用户代码必须放在 `USER CODE BEGIN/END` 区域。
- 任务状态机只负责流程编排；电机协议和舵机 PWM 留在 BSP。
- 中断只做收发和缓存更新，运动、视觉决策和屏幕发送放在主循环。
- 二维码只在任务 1 成功后提交给后续任务，禁止每个任务重复解析原始字符串。
- 任务 8 复用任务 4 时，必须保留“按第二批目标顺序”的切换逻辑。
- 任务 9 的同色匹配仍必须基于第一批实际环位；目标环位用于机械臂水平轴，不再用于底盘环间移动。
- 粗加工区和暂存区的底盘停在中心区域，机械臂通过 Z 轴及水平轴的 1/2/3 号环标定覆盖目标位置；实车调整零点或伸出量后必须同步更新标定和软限位。
- 任何路径参数修改后都要重新检查启停区 1、启停区 2 两条路线。

1. 确认 `Core/Src/main.c` 仍按任务 1～10 的顺序提交和调度状态机，且每个任务只提交一次。

5. 分别验证启停区 1、启停区 2，以及行驶中二维码接收、视觉超时、CAN 故障和任务失败停车。
6. 最后进行任务 1～10 连续运行测试，核对屏幕任务码、抓取计数、放置计数和最终停车位置。

## 17. 现场竞赛任务、决赛变化与评分说明

本节用于说明参赛队在现场需要完成的业务闭环。评分以赛区正式发布的命题要求和评分细则为准；README 中的分值、时间和任务码格式不替代现场裁判的最终解释。

### 17.1 机器人需要读取什么任务信息

当前工程将任务码定义为 15 个有效字符：

```text
XXX+XXX+XXX+XXX
```

四组数字的含义如下：

| 字段 | 含义 | 当前工程的使用方式 |
| --- | --- | --- |
| 第 1 组三位 | 第一批 3 个物料的颜色及搬运顺序 | 例如 `156` 表示按红、黑、浅蓝顺序抓取 |
| 第 2 组三位 | 第一批物料在粗加工区、暂存区的环位 | 三个数字分别对应第一批三个物料的目标环 |
| 第 3 组三位 | 第二批 3 个物料的颜色及搬运顺序 | 例如 `516` 表示按黑、红、浅蓝顺序抓取 |
| 第 4 组三位 | 第二批物料在粗加工区的环位 | 只用于第二批粗加工区平面放置 |

颜色编号按现行初赛规则为：红色 1、黄色 2、蓝色 3、绿色 4、黑色 5、浅蓝 6；环位编号当前使用 1、2、3。任务码由机器人在二维码板前通过 UART4 接收，`BSP/QR.c` 校验格式、颜色范围和环位范围后，`BSP/task_plan.c` 将其转换为两批可执行计划，并同步显示到车载任务码显示装置。

第二批在暂存区不是按第 4 组三位直接摆放，而是按颜色查找第一批中同色物料的实际环位，再将第二批物料码垛到对应的第一批物料上。例如：

```text
156+123+516+231
```

表示第一批按红、黑、浅蓝顺序搬运到 1、2、3 号环；第二批按黑、红、浅蓝顺序搬运，粗加工区目标环为 2、3、1；进入暂存区后，第二批黑、红、浅蓝分别码垛到第一批的黑、红、浅蓝物料上。

决赛的物料形状、颜色以及任务编码和获取方式由现场公布，可能与上述初赛编码不同。因此，本工程的固定 15 字符解析器只能作为当前赛题的默认实现；若决赛现场改变字段长度、颜色编号、目标位置或增加装配字段，应先修改 `QR_TaskCode_t`、`task_plan_t` 和任务状态机，再进行整机联调，不能把未知决赛码强行按初赛格式解释。

### 17.2 现场一轮比赛的完整过程

下面按裁判实际观察到的顺序描述一轮运行。除现场另有公告外，现场决赛流程参照现场初赛流程。

1. **检录、抽签和准备**：队伍按抽签顺序进入指定场地，抽签确定场地号、赛位号和启停区。赛前按规则完成调试；现行细则规定赛前有 5 分钟调试时间，两轮比赛各有 3 分钟调试时间和 3 分钟运行时间。决赛创新实践环节另有最多 4 小时的现场设计、制作、手爪替换和联调时间，该时间不等同于现场运行时间。
2. **任务公布和场地布置**：调试时间剩余 1 分钟时抽取本轮物料搬运任务；剩余 30 秒时机器人必须停止运行并放回抽签确定的出发位置。助理裁判放置二维码板，将物料随机摆放到原料区转盘并启动转盘。二维码板的位置、转盘停止位置和物料颜色可能具有随机性。
3. **一键启动**：裁判统一发出开始指令后开始计时。机器人只能使用车上明确标识的一键启动方式启动一次；运行过程中队员不得再次接触机器人、笔记本电脑或场地物料。
4. **读取任务码**：机器人先移动到二维码板前，读取任务码，校验成功后在车载显示装置上显示完整任务码，并持续显示到本轮结束。读取失败、格式非法或无法形成有效计划时，任务进入错误处理，不能凭猜测执行。
5. **第一批原料区取料**：机器人按第一组三位确定的颜色和顺序，到原料区逐件抓取第一批 3 个物料。每次只能抓取 1 个；必须先把物料放到机器人承载位置，确认承载成功后才能抓取下一个。物料未放到机器人上，不得携带手爪中的物料驶向下一个区域。
6. **第一批粗加工区放置**：机器人携带 1～3 个物料到粗加工区，按第二组三位规定的顺序和环位逐件放置。放置时，物料底面接触地面即视为该次放置完成，位置按此瞬间确定；之后不得再次推动或调整该物料。
7. **第一批取回和暂存**：第一批 3 个物料在粗加工区放置完成后，机器人按原顺序将其取回，运到暂存区，并按相同的目标环位逐件平面放置。第一批暂存放置完成后，机器人返回原料区。
8. **第二批取料和粗加工放置**：机器人按第三组三位确定的颜色和顺序，逐件抓取第二批 3 个物料，再按第四组三位规定的环位放置到粗加工区。第二批的抓取、承载、运输和粗加工区放置约束与第一批相同。
9. **第二批同色码垛**：机器人将第二批物料取回并运到暂存区。每件第二批物料必须找到第一批中颜色一致的下层物料，并按任务顺序放置在其上方；码垛要求物料保持稳定、不掉落。当前工程将前两件保持低位码垛姿态，最后一件完成后抬升并回到料盘方向。
10. **返回启停区和上报统计**：全部搬运完成后，机器人回到抽签确定的启停区并停止。车载显示装置应保留正确任务码，并显示正确抓取数量和正确放置数量。当前工程由任务 10 根据启动区 1/2 选择不同的最后一段返程路线。

### 17.3 什么情况算完成

一轮任务同时满足以下条件，才可视为完整完成：

- 二维码任务信息读取正确，并持续正确显示；
- 两批物料均按任务码规定的颜色和顺序完成抓取；
- 第一批和第二批粗加工区物料按规定环位完成平面放置；
- 第一批暂存区物料按规定环位完成平面放置；
- 第二批暂存区物料与第一批对应物料颜色一致，并稳定完成码垛；
- 机器人在规定运行时间内回到抽签确定的启停区；
- 返回后显示的正确抓取数、正确放置数与裁判按任务要求核对的数量一致。

本工程当前任务包含“搬运、平面放置和同色码垛”，没有单独的零件装配工序。决赛创新实践环节可能要求现场制作或更换手爪等零部件并完成调试，这属于赛前工程实践；如果现场决赛任务另行发布装配动作，则需要新增装配状态、执行器动作和完成判定，不能默认现有任务 1～10 已覆盖装配。

### 17.4 评分口径和时间因素

现场决赛总成绩由创新实践和现场决赛两部分组成：创新实践 30 分，现场决赛 70 分。现场决赛每队有两次运行机会，取两次运行中的最好成绩；最终计分以官方现场决赛评分表为准。

官方现场运行的计分点包括：

| 计分点 | 判定方式 |
| --- | --- |
| 正确读取二维码并显示 | 任务码读取正确，且车载显示装置正确显示 |
| 任务码持续显示 | 正确任务码持续显示到本轮结束 |
| 正确抓取 | 每个物料按规定顺序抓取并成功放到机器人承载位置 |
| 平面放置准确度 | 以物料底面接触地面时的位置为准，根据能看到的圆环外圈确定环号；环 1～6 的官方分值依次为 15、10、7、5、3、1，环外或倾倒为 0 |
| 码垛 | 第二批物料放在颜色一致的第一批物料上且不掉落；码垛分值按对应平面放置分值计算 |
| 返回启停区 | 在规定时间内完成全部流程并回到抽签确定的启停区 |
| 统计信息 | 完成返回后，正确抓取数量和正确放置数量均正确显示 |

时间采用连续计时，会影响“是否在规定时间内完成”以及同分排序。决赛同分时，先比较现场决赛得分，再比较完成全部流程所用时间；分高且用时少者优先。时间不是用来替代物料顺序、放置准确度或码垛稳定性的分数，不能通过提前结束或跳过动作获得完成判定。

以下行为会使相关动作不计分或导致本轮结束：运行中人工触碰机器人、电脑或物料；物料尚未放到机器人承载位置就驶向下一区域；已接触地面的物料被再次推动；机器人在车道外行驶、长时间停止、原地高速打滑，或队员取出掉落物料。具体处理以现场裁判判定为准。

### 17.5 初赛与决赛的变化

根据现行命题要求，决赛现场运行流程**原则上参照初赛**：仍然是读取任务、按顺序取料、粗加工区放置、取回、暂存区放置、第二批同色码垛并返回启停区。因此当前工程的任务 1～10 可以作为决赛流程骨架。

决赛的主要变化在于：

- 决赛物料的形状和颜色种类可能增加，现场任务编码及获取方式由组委会公布，不保证继续使用初赛的固定 15 字符格式；
- 创新实践环节要求根据现场抽签物料完成手爪替换、零部件制作和机器人联调，重点考察现场设计制造、工程实施、协作和调试能力；
- 决赛更强调对未知物料、颜色差异、尺寸变化和任务码变化的适应能力，而不是只验证一组固定路径参数。

如果现场公告明确说明决赛任务与初赛完全相同，则无需另造一套评分规则，直接沿用本节的初赛任务流程和官方评分表；如果现场发布了新的编码或装配要求，应以现场公告为准，并在软件中增加对应的数据模型和状态机。
