# 串口屏选择启停区并启动

UART5 已配置为 115200 baud、8位数据、无校验、1位停止位。
STM32 的 TX 为 PC12，接屏幕 RX；STM32 的 RX 为 PD2，接屏幕 TX，双方共地。

屏幕按钮的触摸释放事件：

| 按钮 | 屏幕事件代码 | 实际发送 | 执行结果 |
| --- | --- | --- | --- |
| 启停区1启动 | `printh 31` | 单字节 `0x31`，字符 `1` | 从区1开始执行完整任务1～10，最后返回区1 |
| 启停区2启动 | `printh 32` | 单字节 `0x32`，字符 `2` | 从区2开始执行完整任务1～10，最后返回区2 |

启动命令无需换行、字符串前缀或 `FF FF FF` 结束符。
MCU 向屏幕更新 t0、t3、t5 的显示指令仍按原协议追加 `FF FF FF`。

## 启动行为

上电完成原有外设、电机和 IMU 准备后等待命令，已删除5秒自动启动。
UART5 接收在准备流程开始时开启，准备期间收到的首条有效命令会保存，准备结束后才执行。
中断仅记录区域并挂接下一字节接收，机械臂和底盘动作均在主循环执行。
首条有效命令锁定本次上电的路线，重复按钮或切换按钮均不改变本轮路线。
完成后重新摆放车辆并复位，再选择下一轮路线。

## 已确认的两区路线

两区初始均车头朝场地图左，所有前后左右使用车体坐标。

| 流程 | 启停区1 | 启停区2 |
| --- | --- | --- |
| 任务1 | 前进100mm → 左移1050mm并归零 → 前进150mm → 扫码 | 前进100mm → 右移1050mm并归零 → 前进150mm → 扫码 |
| 任务2～9 | 使用现有流程 | 共用相同流程 |
| 任务10 | 回到暂存区2号环 → 左移1900mm → 后退1050mm → 停机 | 回到暂存区2号环 → 左移1900mm → 前进980mm → 停机 |

任务10回中根据第二批最后颜色在第一批中的实际环位确定，不能直接使用第二批粗加工环号。
任务10最后一段车头朝场地图下；区2最后一段按当前路线以车体前向移动980mm。
既有回退修复、连续低位放置、码垛优化、底盘400ms余量、料盘400ms等待和张爪前500ms等待保留。

## 文件和调参位置

- `Core/Src/main.c`：等待启动命令、同时设置任务1起点与任务10终点、任务1～10调度。
- `BSP/screen.c`、`BSP/screen.h`：单字节接收、首次启动锁定、串口错误恢复，保留原显示功能。
- `BSP/start_zone.h`：两区公共枚举。
- `BSP/QR.c`：工程唯一 HAL UART 完成/错误回调，分发到屏幕接收处理。
- `Core/Src/usart.c`、`Core/Src/stm32f4xx_it.c`、`Core/Inc/stm32f4xx_it.h`、`Engineering_innovation.ioc`：UART5中断配置及入口。
- `APP/task1_start_qr.h`：区1横移参数 `TASK1_START_QR_LEFT_MM`，区2横移参数 `TASK1_START_QR_RIGHT_MM`。
- `APP/task10_return_home.h`：区1返程参数 `TASK10_RETURN_HOME_BACKWARD_MM`，区2返程参数 `TASK10_RETURN_HOME_ZONE2_FORWARD_MM`。

调试串口 USART6 就绪日志为 `waiting_uart5_0x31_zone1_or_0x32_zone2`；
启动日志为 `screen_start_zone1` 或 `screen_start_zone2`，区2横移/返程日志分别包含 `right` / `forward`。

## 已进行的验证

固件完成 ARM 编译链接，本次修改的7个C文件通过 `-Wall -Wextra -Werror` 检查。
完整构建未再包含旧的惯导闭环函数；当前底盘只保留速度模式、位置增量下发和编码器速度解算。
`tmp/start_zone_regression/run.ps1` 检查命令、回调分发、错误恢复、任务1和任务10路线与故障停车。
`tmp/ground_place_regression/run.ps1` 检查既有18组地面放置、36组码垛和22个故障用例。
这些为主机回归及编译检查，尚未在实车上烧录验证 UART5 电气通信和路线距离。
